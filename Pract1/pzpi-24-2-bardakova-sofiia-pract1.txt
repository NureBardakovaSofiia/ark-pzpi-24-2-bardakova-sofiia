1 ПРАВИЛА ОФОРМЛЕННЯ ПРОГРАМНОГО КОДУ МОВИ JAVA
1.1 Мета заняття

Ознайомитися з основними рекомендаціями щодо написання чистого, ефективного та підтримуваного коду для різних мов програмування, а також навчитися аналізувати та рефакторити код для покращення його якості.

1.2 Завдання

Необхідно обрати мову програмування, дослідити основні рекомендації для написання якісного коду у цій мові, продемонструвати ці рекомендації на прикладах коду, обґрунтувати кожну рекомендацію і надати детальні пояснення. Для кожного прикладу мають бути наведені фрагменти коду.

1.3 Опис виконаної роботи
1.3.1 Мова програмування Java

Java - це високорівнева об’єктно-орієнтована мова програмування, основними перевагами якої є простота, надійність і кросплатформеність. Вона створена за принципом “Пиши один раз, запускай будь-де”, тому програми, розроблені на Java, можуть працювати на різних пристроях та операційних системах за наявності віртуальної машини Java (JVM) [6].
Java має надійну та гнучку архітектуру. Вона використовує строгу типізацію, що допомагає виявляти помилки ще під час компіляції, та автоматичне керування пам’яттю за допомогою Garbage Collection. Мова також має велику стандартну бібліотеку, яка містить готові інструменти для роботи з даними, файлами, мережами та іншими завданнями, що спрощує й прискорює розробку програм [6].


1.3.2 Правила іменування
1.3.2.1 Правила найменування класів

Рекомендація: використовуйте UpperCamelCase для класів та інтерфейсів.
Опис: Назви класів та інтерфейсів повинні починатися з великої літери, а кожне наступне слово також починається з великої літери. Для назв рекомендується використовувати зрозумілі іменники або іменникові словосполучення. Oracle також рекомендує уникати непотрібних скорочень [1].
Приклад:
// Поганий приклад
class studentdata {
}

// Гарний приклад
class StudentData {
}
Пояснення рекомендації: Важливо дотримуватись цієї рекомендації, тому що UpperCamelCase дозволяє одразу відрізнити назву класу від назви змінної або методу. Як наслідок недотримання рекомендації, код стає менш зрозумілим і складнішим для читання та підтримки, оскільки важче одразу визначити, де назва класу, а де змінна або метод. Зрозумілі назви класів полегшують пошук потрібних компонентів та роботу з великими проєктами.

1.3.2.2 Правила найменування пакетів

Рекомендація: Використовуйте малі літери для назв пакетів.
Опис: Назви пакетів у Java пишуться маленькими літерами. Для великих проєктів рекомендується використовувати унікальну структуру на основі доменного імені, наприклад com.example.project [1].
Приклад:
// Поганий приклад
package MyProject;

// Гарний приклад
package myproject;
package studentdata;
package com.example.myproject;
Пояснення рекомендації: Дотримання цього правила важливе, оскільки використання малих літер дозволяє легко відрізняти назви пакетів від назв класів, які починаються з великої літери. Недотримання рекомендації може ускладнити розуміння структури проєкту, а правильне найменування пакетів спрощує його організацію та робить проєкт зрозумілим для будь-якого Java-розробника.

1.3.2.3 Правила найменування логічних змінних і методів

Рекомендація: Використовуйте префікс is для логічних змінних і методів, які повертають значення boolean. Для методів, що встановлюють значення, використовуйте префікс set. Також залежно від змісту можна використовувати has, can та should [5].
Опис: Назви логічних змінних і методів повинні чітко описувати умову або стан, який вони представляють. Використання відповідних префіксів допомагає одразу зрозуміти, що елемент має логічне значення [5].
Приклад:
// Поганий приклад
boolean visible;
boolean finished;

// Гарний приклад
boolean isVisible;
boolean isFinished;
public void setFound(boolean isFound) {
    this.found = isFound;
}
Пояснення рекомендації: Дотримання цього правила допомагає відразу зрозуміти, що метод повертає логічне значення та яку саме умову він перевіряє. Використання префіксів is, has, can і should робить назви методів зрозумілими та однозначними, що полегшує читання й підтримку коду. Недотримання правила може зробити призначення логічного методу менш зрозумілим, через що розробнику доведеться додатково переглядати його реалізацію, щоб зрозуміти, що саме він перевіряє.

1.3.3 Структура коду
1.3.3.1 Порядок розташування елементів усередині класу

Рекомендація: Розташовуйте елементи класу в послідовному та логічному порядку: спочатку статичні поля, потім нестатичні поля, конструктори, а після них методи [3].
Опис: Елементи класу потрібно групувати відповідно до їх призначення, щоб структура класу була зрозумілою та передбачуваною. Методи також рекомендується розташовувати логічно, наприклад групувати пов’язані між собою методи - ті, які працюють з однією сутністю або виконують схожі завдання.  [3].
Приклад:
public class Student {
    // Поля
    private static int studentCount;
    private String name;
    private int age;

    // Конструктор
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Методи
    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }
}
Пояснення рекомендації: Дотримання встановленого порядку робить структуру класу передбачуваною, полегшує пошук потрібного коду та внесення змін у майбутньому, особливо під час роботи над великими проєктами. . Недотримання рекомендації може зробити клас менш організованим і ускладнити його читання та подальшу підтримку.

1.3.3.2 Структура вихідного файлу

Рекомендація: Дотримуйтеся встановленого порядку розташування основних частин Java-файлу: спочатку інформація про ліцензію або авторські права, потім оголошення пакета, імпорти та один клас верхнього рівня [3].
Опис: Java-файл повинен мати чітку структуру. Між кожною присутньою частиною рекомендується залишати один порожній рядок.
Приклад:
// Copyright (c) 2026 Sofiia Bardakova.

package com.example.student;

import java.util.List;

public class Student {

    // Class contents
}
Пояснення рекомендації: Дотримання визначеного порядку робить структуру файлу передбачуваною та полегшує його читання. Недотримання рекомендації може ускладнити пошук пакета, імпортів або основного класу, а правильна структура спрощує подальшу підтримку коду.

1.3.4 Стильові рекомендації
1.3.4.1 Використання фігурних дужок

Рекомендація: Розміщуйте відкриваючу фігурну дужку { в кінці того самого рядка, де починається відповідний блок коду [3].
Опис: Відкриваюча дужка повинна розташовуватися після оголошення класу, методу, умови, циклу або іншої конструкції, а закриваюча - на окремому рядку на тому самому рівні відступу, що й початок конструкції.
Приклад:
// Поганий приклад
if (age >= 18)
{
    System.out.println("Adult");
}

// Гарний приклад
if (age >= 18) {
    System.out.println("Adult");
}
Пояснення рекомендації: Такий формат забезпечує єдине оформлення блоків коду та дозволяє одразу побачити, до якої конструкції належить блок. Недотримання правила робить форматування коду непослідовним і може ускладнити його читання. Єдине розташування фігурних дужок робить структуру блоків коду передбачуваною, що полегшує його читання, редагування та подальшу підтримку.

1.3.4.2 Пробіли навколо операторів

Рекомендація: Використовуйте пробіли навколо бінарних операторів (+, -, =, ==, >, < тощо) [3].
Опис: Пробіл повинен розташовуватися з обох боків оператора, що робить вираз візуально зрозумілішим.
Приклад:
// Поганий приклад
int result=a+b;
if(age>=18){ }

// Гарний приклад
int result = a + b;
if (age >= 18) { }
Пояснення рекомендації: Пробіли навколо операторів покращують читабельність виразів і допомагають швидше зрозуміти логіку коду. Недотримання цього правила робить код візуально менш зрозумілим і складнішим для читання. Єдине форматування пробілів спрощує читання та редагування коду в майбутньому.


1.3.4.3 Довжина рядка

Рекомендація: Не перевищуйте встановлену максимальну довжину рядка Java-коду - 100 символів [3].
Опис: Якщо рядок коду занадто довгий, його потрібно перенести на наступний рядок відповідно до правил форматування.
Приклад:
// Поганий приклад
public void calculateStudentAverageGrade(Student student, List<Double> grades, boolean includeExtraCredits) { }

// Гарний приклад
public void calculateStudentAverageGrade(
        Student student,
        List<Double> grades,
        boolean includeExtraCredits) {
}
Пояснення рекомендації: Обмеження довжини рядків робить код зручнішим для перегляду та запобігає необхідності горизонтального прокручування. Надто довгі рядки можуть ускладнювати читання та редагування коду. Короткі та правильно перенесені рядки полегшують перегляд, редагування й підтримку коду в майбутньому.

1.3.5 Принципи рефакторингу
1.3.5.1 Рефакторинг методом Extract Method

Рекомендація: Використовуйте Extract Method для виділення окремих частин складного методу в самостійні методи з чітким призначенням [2].
Опис: Цей метод рефакторингу передбачає винесення частини коду з існуючого методу в новий метод без зміни поведінки програми.
Приклад:
// До рефакторингу
public void processStudent(Student student) {
    System.out.println(student.getName());

    if (student.getGrade() >= 60) {
        System.out.println("Passed");
    }
}

// Після рефакторингу
public void processStudent(Student student) {
    printStudentName(student);
    checkResult(student);
}

private void printStudentName(Student student) {
    System.out.println(student.getName());
}

private void checkResult(Student student) {
    if (student.getGrade() >= 60) {
        System.out.println("Passed");
    }
}
Пояснення рекомендації: Виділення окремих логічних частин коду робить методи коротшими та зрозумілішими. Недотримання цього принципу може призвести до появи великих і складних методів, які важче читати, тестувати та змінювати. Поділ складного коду на невеликі методи спрощує пошук помилок, тестування та внесення змін у програму в майбутньому.
1.3.6 Тестування та документування коду.
1.3.6.1 Рекомендації щодо тестування коду

Рекомендація: Використовуйте автоматизовані тести для перевірки правильності роботи окремих частин програми.
Опис: У Java для автоматизованого тестування можна використовувати JUnit. Тести створюються окремо від основного коду та перевіряють, чи повертають методи очікувані результати [5].
Приклад:
// Основний код
public int add(int a, int b) {
    return a + b;
}

// Тест
@Test
void shouldAddNumbers() {
    Calculator calculator = new Calculator();

    assertEquals(5, calculator.add(2, 3));
}
Пояснення рекомендації: Автоматизовані тести дозволяють швидко перевіряти правильність роботи окремих методів і своєчасно виявляти помилки. Недотримання цієї рекомендації може призвести до того, що помилки залишаться непоміченими або будуть виявлені лише під час використання програми. Наявність тестів спрощує перевірку коду та внесення змін у програму в майбутньому.


1.3.6.2 Рекомендації щодо документування коду

Рекомендація: Документуйте призначення класів, методів і їх параметрів за допомогою Javadoc [4].
Опис: Javadoc використовується для створення документації до Java-коду. Коментарі Javadoc розміщуються перед класами та методами й можуть містити опис їх призначення, параметрів і результату роботи.
Приклад:
/**
 * Calculates the sum of two numbers.
 *
 * @param a first number
 * @param b second number
 * @return sum of two numbers
 */
public int add(int a, int b) {
    return a + b;
}
Пояснення рекомендації: Документування коду допомагає швидко зрозуміти призначення класів і методів без необхідності детально аналізувати їх реалізацію. Недотримання цієї рекомендації може ускладнити розуміння коду та роботу з ним для інших розробників. Наявність актуальної документації спрощує підтримку, використання та подальше розширення програми.

1.4 Висновки

У ході виконання роботи було досліджено основні рекомендації щодо написання якісного, зрозумілого та підтримуваного коду мовою Java. Було розглянуто правила іменування класів, пакетів і логічних змінних та методів, вимоги до структури класів і вихідних файлів, стильові правила оформлення коду, а також принципи рефакторингу, тестування та документування. Для кожної рекомендації наведено приклади коду та пояснено її практичне значення. Дотримання цих рекомендацій допомагає зробити код більш структурованим, читабельним і зручним для подальшого тестування, редагування та підтримки.
